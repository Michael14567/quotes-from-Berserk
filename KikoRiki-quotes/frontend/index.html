Журнал сценария
    
        
    Как рассказать об этом на собеседовании
          
    «Я собрал учебный сервис цитат на Python и PostgreSQL и развернул его в Docker Compose на Linux-сервере. Nginx раздаёт страницу и направляет API-запросы, Caddy обеспечивает HTTPS. Выбранная цитата передаётся через Kafka API в отдельный сервис уведомлений, который отправляет её в Telegram».
    
          
    «Уведомления и обработчик бота работают на моём компьютере, подключаясь к серверной базе и брокерам через SSH-туннель. Задачи привязаны к Telegram-чату и доступны из браузера и бота. Токен бота остаётся на компьютере, секреты исключены из Git».
    
          
    «Из практики сопровождения: по логам обнаружил потерю доступа обработчиков к базе после перезапуска туннеля. Исправил переподключение и проверил восстановление после принудительного обрыва. При обновлении цитат сделал резервную копию и заменил данные одной SQL-транзакцией».
    
          
    Что можно показать
    • Linux, Docker Compose, Nginx, DNS и HTTPS.
    • Python, SQL, API и автоматические тесты.
    • Producer и consumer, три брокера, разбор сбоев доставки.
    • GitLab CI: конфигурация тестов, сборки образов и deploy через Ansible.
    Границы учебного стенда
    • Три брокера — три контейнера на одном сервере; отказ самого сервера они не переживут.
    • При выключенном компьютере обработчики Telegram не работают.
    • CI/CD подготовлен, но запуск GitLab пока заблокирован подтверждением аккаунта.
    • Minikube — отдельный учебный стенд. Банковские системы, Service Manager и мониторинг ELK/Grafana/Zabbix здесь не реализованы.
    
          
    Kafka использует транзакции и идемпотентного producer; consumer читает подтверждённые записи. Отправка в Telegram не входит в транзакцию Kafka: при сбое между доставкой и commit позиции возможен дубль.
