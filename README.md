# Цитатник Смешариков

Небольшой сервис, который показывает случайную цитату и отправляет её в Telegram. Цитату получает пользователь, привязавший свой браузер к боту через QR-код.

Проект использует FastAPI, PostgreSQL, Nginx и Redpanda (брокер с поддержкой Kafka API). Все компоненты запускаются через Docker Compose.

```text
Браузер → Nginx → FastAPI → PostgreSQL
                      ↓
                Redpanda / Kafka → сервис уведомлений → Telegram
```

Для привязки браузера отдельный процесс получает команды `/start` от Telegram. Три брокера Redpanda хранят по реплике топика `quote-clicks`.

Для серверного размещения обработчик Telegram можно запустить на своём компьютере: он подключается к базе и Kafka на сервере через SSH-туннель. Инструкция — в [deploy/README.md](deploy/README.md#сайт-на-сервере-уведомления-на-компьютере).

Код сервисов находится в `KikoRiki-quotes/backend/main` и `KikoRiki-quotes/backend/notification`. Страница находится отдельно в `KikoRiki-quotes/frontend`.

## Практика и задачи

На странице есть три учебных раздела:

- «Тренироваться»: 16 заданий по PostgreSQL и Linux, поле для решения, подсказки и эталонные ответы. Это самопроверка в браузере; введённые команды и запросы не выполняются.
- «Карта»: пошаговая имитация получения цитаты, её отправки в Telegram, привязки браузера и сохранения задач. Можно нажать на компонент и прочитать его назначение и подход к диагностике. Здесь же описаны проект, его стек и ограничения.
- «Задачи»: личный список на сегодня по московскому времени. Требуется привязанный Telegram. Задачи сохраняются в PostgreSQL по ID чата; разные браузеры, привязанные к одному чату, видят один список. При выполнении задачи на сайте взлетает и взрывается фейерверк; при уменьшении анимации остаётся текстовое подтверждение.

В личном чате бота `/tasks` показывает первые 10 задач за сегодня с кнопками выполнения, `/add Название задачи` добавляет задачу. Полный список доступен на сайте. Изменения из Telegram подгружаются на сайте раз в 15 секунд, пока открыт раздел задач, а также кнопкой «Обновить». Обработчик бота на компьютере должен быть включён. Команды и кнопки используют [Telegram Bot API](https://core.telegram.org/bots/api).

После обновления существующей базы примените `telegram.sql` командой из раздела ниже: миграция также создаёт таблицу `daily_tasks`. Начальное заполнение пустой базы и Ansible используют этот же файл.

## Запуск

Установите и запустите Docker Desktop. В PowerShell из корня репозитория:

```powershell
cd KikoRiki-quotes
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
py -3.12 setup_database.py
docker compose -f compose.yaml -f ../deploy/compose.https.local.yaml up -d --build
docker compose -f compose.yaml -f ../deploy/compose.https.local.yaml ps
```

Откройте [https://localhost:8443](https://localhost:8443). Локальный сертификат выпущен собственным центром Caddy, поэтому браузер не доверяет ему автоматически. Проверять его можно через сохранённый локальный корневой сертификат, как описано в [инструкции](deploy/README.md#локальный-https). Сервис цитат работает без настроек Telegram.

## Уведомления в Telegram

Создайте бота через [BotFather](https://t.me/BotFather) и укажите его токен и имя в `KikoRiki-quotes/.env`:

```env
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_BOT_USERNAME=имя_бота_без_собаки
SESSION_COOKIE_SECURE=false
```

Файл `.env` хранится локально и исключён из Git. После изменения настроек пересоздайте сервисы:

```powershell
docker compose -f compose.yaml -f ../deploy/compose.https.local.yaml up -d --build
```

На сайте нажмите «Привязать Telegram», отсканируйте QR-код и нажмите Start в боте. Можно также открыть бота по ссылке под кодом. Код действует пять минут и подходит для одной привязки. Не передавайте его другим людям. При смене браузера или очистке cookie привязку нужно повторить. Кнопка «Отвязать Telegram» удаляет связь.

Получение обновлений через `getUpdates` должно быть запущено только в одном экземпляре бота. Не включайте `telegram-bot` одновременно в Compose и Minikube с одним токеном.

На существующей базе после обновления проекта примените миграцию:

```powershell
docker compose exec -T db psql -v ON_ERROR_STOP=1 -U quotes -d quotes -f /docker-entrypoint-initdb.d/03-telegram.sql
```

## API и диагностика

Swagger доступен на [localhost:8000/docs](http://localhost:8000/docs). Основные маршруты:

- `GET /smeshariki-quotes` — цитаты; параметр `character` фильтрует их по персонажу.
- `POST /quote-click` — событие с выбранной цитатой: `{"quote_id": 1}`.
- `POST /telegram/link`, `GET /telegram/status`, `DELETE /telegram/link` — привязка и отвязка Telegram.
- `GET /tasks`, `POST /tasks` с `{"title": "Повторить SQL"}` — задачи текущего пользователя за сегодня.
- `PATCH /tasks/{id}` с `{"done": true}`, `DELETE /tasks/{id}` — выполнение и удаление своей задачи.

Nginx направляет запросы с префиксом `/api/` в FastAPI. Посмотреть логи и состояние брокеров:

```powershell
docker compose logs --tail 50 app notification telegram-bot
docker compose exec kafka rpk cluster info -X brokers=kafka:9092
docker compose exec kafka rpk topic describe quote-clicks -p -X brokers=kafka:9092
```

События Kafka отправляются в транзакции с `enable.idempotence` и `acks=all`. Consumer читает подтверждённые транзакции. При сбое после принятия сообщения Telegram и до сохранения позиции Kafka уведомление может прийти повторно; транзакция Kafka не охватывает Telegram API.

Данные PostgreSQL и брокеров сохраняются в Docker volumes. Команда `docker compose -f compose.yaml -f ../deploy/compose.https.local.yaml down` останавливает сервисы без удаления данных; добавление `-v` удаляет volumes. SQL-файлы инициализации применяются при создании пустой базы. Пароль хранится в игнорируемом файле `KikoRiki-quotes/.secrets/postgres_password` и передаётся контейнерам через Compose secrets. Не удаляйте и не меняйте этот файл без согласованной смены пароля PostgreSQL: переменная и файл инициализации не меняют пароль уже существующей базы.

## Данные пользователей

Задачи сохраняют ID чата владельца, название, дату по Москве, отметку выполнения и время создания. Для добавленных из Telegram задач также хранится служебный ID обновления, чтобы повторная обработка не создавала копии. Названия задач не отправляются в Kafka и не пишутся в логи приложения. После отвязки браузера задачи остаются за Telegram-чатом; при повторной привязке того же чата список снова доступен. Отдельную задачу можно удалить на сайте.

Для привязки браузера к боту PostgreSQL сохраняет ID чата Telegram и хеш случайной сессии браузера. При создании QR-кода также сохраняются хеш одноразового кода и время его истечения; после привязки они очищаются. Неиспользованный истёкший код остаётся в базе до повторной привязки или отвязки. В браузере хранится cookie `quotes_session`; без него нельзя определить получателя уведомления. При отвязке запись удаляется. Пока пользователь не привязал Telegram, его ID чата не сохраняется.

В Kafka события содержат хеш сессии и время нажатия; срок хранения настроен на 24 часа, фактическое удаление выполняется брокером асинхронно. В базе также хранится служебная позиция обработки обновлений бота. Обычные access-логи Nginx и Uvicorn выключены; ошибки инфраструктуры всё ещё могут содержать технические данные. Telegram обрабатывает данные в соответствии со своими правилами. Для публичного сервиса нужны домен, открытые порты, резервное копирование и ограничение доступа к инфраструктуре.
